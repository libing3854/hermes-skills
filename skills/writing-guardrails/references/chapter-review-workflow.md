# 章节审核与压缩工作流

当用户要求"审核并修改某章"或"压缩字数到X范围"时，按以下流程执行。

## 步骤1：AI高频词扫描

用 Python 脚本一次性扫描所有禁用词和高频词（比逐个 search_files 高效）：

```python
python3 -c "
import re
with open('章节文件', 'r') as f:
    text = f.read()

# 禁用词扫描
banned = {
    '微微': 0, '缓缓': 0, '仿佛': 0, '某种': 0,
    '深吸一口气': 0, '不禁': 0, '竟然': 0, '居然': 0, '原来': 0,
}
for w in banned:
    banned[w] = len(re.findall(w, text))
    print(f'{w}: {banned[w]}')

# 重复句式扫描
patterns = {
    '不是...是': len(re.findall(r'不是.{0,10}是', text)),
    '然后': len(re.findall('然后', text)),
    '那种': len(re.findall('那种', text)),
    '他的眼睛': len(re.findall('他的眼睛', text)),
    '他的声音': len(re.findall('他的声音', text)),
}
print('\n重复表达:')
for p, c in sorted(patterns.items(), key=lambda x: -x[1]):
    print(f'  {p}: {c}次')
"
```

阈值参见 writing-guardrails SKILL.md 的"AI高频词数量阈值"段落。

**"不是X，是Y"是最高频AI句式**（实战：单章可达21次）。必须在扫描阶段就统计，修复策略见 story-deslop Gate B。

**"那种"是常见AI填充词**（实战：单章可达7次）。修复极简单——删"那种"直接说名词即可。

## 步骤2：字数统计

用 Python 统计，注意多种计量口径：

```python
python3 -c "
import re
with open('章节文件', 'r') as f:
    text = f.read()
clean = re.sub(r'\s+', '', text)
chinese = len(re.findall(r'[\u4e00-\u9fff]', text))
punct = len(re.findall(r'[\u3000-\u303f\uff00-\uffef]', text))
print(f'总字数（非空白字符）: {len(clean)}')
print(f'中文字符+标点: {chinese + punct}')
print(f'纯中文字: {chinese}')
"
```

- "字数"通常取 总字数（非空白字符）或 中文字符+标点，与用户确认口径
- 对比目标范围，计算需压缩/扩展的字数差

## 步骤3：质量审核维度

| 维度 | 检查内容 |
|------|----------|
| 剧情推进 | 是否有实质性情节进展？有无水字数的无效段落？ |
| 人物塑造 | 对话是否符合角色性格？行为是否合理？ |
| 逻辑衔接 | 与前后章节是否连贯？伏笔是否埋设/回收？ |
| AI味 | 高频词是否超标？有无模板化句式？（重点检查"不是X是Y"和"那种"） |
| 结尾 | 是否为动作/场景收尾（非总结感慨）？ |

## 步骤4：压缩策略（当需减少字数时）

优先级从高到低：

### 4a. 删除重复解释
同一信息被多个角色或多个段落重复阐述 → 保留最有力的一次，删除其余。

### 4b. 合并冗余对话
多轮简短问答可以合并为单句陈述，特别是揭示性对话。

### 4c. 精简修饰语
删除不影响理解的修饰词和冗余并列。

### 4d. 压缩过渡段落
删除纯过渡性的叙述，直接进入内容。

### 4e. 合并碎片句
AI写作常把一个完整意思用多个句号断成碎片。合并为流畅长句可显著减少字数且提升可读性。

示例：
```
"不是语言。不是声音。是一种感觉。一种归属感。流浪的人终于看到了家的灯光。海上漂泊一辈子的水手终于看到了港口的灯塔。那种温暖。那种安全。那种被接纳的感觉。"
→ "一种归属感。流浪的人终于看到了家的灯光，漂泊的水手终于看到了港口的灯塔。温暖，安全，被接纳。"
```

### 4f. 修复"不是X，是Y"句式
此句式既是AI味问题又是字数膨胀源。修复后通常能减少5-15%字数。

修复策略：
- 有修辞冲击力的保留（如"不是恐惧。是遗憾。"）
- 无特殊修辞价值的改为肯定句
- 同一段落超2处必定改写

### 4g. 保留禁区（不可压缩）
- 核心场景的细节描写
- 关键信息揭示（身份、动机、计划）
- 角色标志性台词
- 章末点题宣言

## 步骤5：执行编辑

**逐条替换，不要用多hunk patch。** 如果一个hunk匹配失败，整个patch被拒绝，所有修改都丢失。逐条调用 patch(mode='replace')，每次只做一处替换。

实战教训（第243章）：首次尝试用一个大patch包含20处修改，全部因第3个hunk匹配失败而回滚。改为逐条replace后全部成功。

## 步骤6：验证

1. 字数验证：重新运行步骤2脚本，确认在目标范围内
2. AI词验证：重新运行步骤1扫描，确认修改未引入新高频词
3. 重复句式验证：确认"不是X是Y"和"那种"等已降至合理水平
4. 流畅性验证：通读修改后全文，检查衔接是否自然

## 注意事项

- 压缩时不改变情节走向和信息量，只削减冗余表达
- 每次 patch 的 old_string 要包含足够上下文以确保唯一匹配
- 目标字数范围由用户指定；常见：4500-5500（短章）、5000-6000（标准章）、6000-8000（长章）
- 压缩比例建议：第一次宁可少删，过头后补回来的内容风格容易不一致
