# TTS Integration Patterns for Cron Jobs

> 研究时间：2026-05-27
> 背景：给 5 个定时任务技能添加 TTS 语音功能时总结的模式

## 核心限制

**no_agent 模式无法使用 TTS。** `text_to_speech` 是 LLM 工具，只有 agent 模式（有 LLM 参与）的 cron 任务才能调用。纯脚本模式（`no_agent=true`）的 cron 任务无法使用。

解决方案：
- 改为 agent 模式（消耗 token）
- 在 Python 脚本中用 edge-tts 等本地 TTS 库（不消耗 token，需安装）
- 跳过（冰哥可能决定不需要）

## TTS 内容分级

| 级别 | 字符限制 | 适用场景 | 示例 |
|------|---------|---------|------|
| 完整版 | 3000 | 每日早报等核心播报 | 天气+新闻+物价+黄历+星座+寄语 |
| 简短版 | 1500 | 金融看板、周报等辅助播报 | 核心指标+异动+一句话总结 |

## 每个技能 TTS 集成必须包含

1. **编入编号执行流程** — TTS 步骤必须有编号（如"步骤5"），不能只是额外说明，否则执行时可能被跳过
2. **语音版提示** — 在文本消息末尾追加 `🎧 语音版已单独发送`（完整版早报可省略，因为内容一致）
3. **自检清单** — 添加 TTS 相关检查项（字符限制、路径、生成成功）

## 文件命名规范

```
{前缀}_brief_YYYYMMDD_HHMM.mp3   # 每日多次任务（需 HHMM 区分）
{前缀}_brief_YYYYMMDD.mp3         # 每日/每周一次任务（无需 HHMM）
```

统一保存到 `~/voice-memos/`

## 语气风格匹配

每个任务的 TTS 语气应与其定位匹配：
- 早报 → 新闻主播，亲切自然
- 金融 → 财经播报，简洁专业
- AI/科技 → 科技资讯，轻松专业
- 开发者 → 社区播报，轻松有料

## 审核流程建议

修改多个技能时的推荐审核流程：
1. 先完成所有修改
2. 让大莉M做深度审核（检查流程兼容性、遗漏、一致性）
3. 根据审核结果修复
4. 让大莉D做最终确认
