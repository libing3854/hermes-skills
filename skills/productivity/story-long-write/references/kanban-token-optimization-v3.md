# kanban任务Token优化指南 v3

> 基于2026-06-09实战：第八批写作+修改+拆分+审核全流程，总结最新优化方案。

## 新增优化方案（2026-06-09）

### 方案K-直接编辑 vs 看板任务

**核心原则**：简单批量操作直接编辑，复杂修改才用kanban任务。

**决策矩阵**：

| 操作类型 | 推荐方式 | 原因 |
|----------|---------|------|
| sed批量替换禁用词（仿佛/某种等） | **直接编辑**（terminal） | 简单、快速、无需等待 |
| 扩充/压缩章节内容 | **直接编辑**（terminal） | 需要判断，适合主会话 |
| 重写整章/大幅修改 | **kanban任务**（闪莉） | 复杂、需要上下文 |
| 多章统一修改 | **kanban任务**（闪莉） | 批量操作、需要一致性 |
| "像"比喻削减 | **kanban任务**（莉莉） | 需要逐章判断保留哪些 |

**直接编辑示例**：
```bash
# 批量替换"仿佛"
for f in 第21[89]*.md 第22[012]*.md; do
  sed -i '' 's/仿佛/如/g' "$f"
done

# 验证替换结果
grep -c '仿佛' 第21[89]*.md 第22[012]*.md
```

**判断标准**：
- 如果操作可以用一行sed命令完成 → 直接编辑
- 如果需要理解上下文才能修改 → kanban任务
- 如果用户说"你改一下吧闪莉太慢了" → 直接编辑

### 方案L-修改任务拆分粒度

**问题**：一个修改任务处理多个问题类型，导致迭代预算耗尽。

**正确做法**：按问题类型拆分修改任务

| 问题类型 | 任务粒度 | 执行者 |
|----------|---------|--------|
| 禁用词替换（仿佛/某种等） | 全批一次性 | 直接编辑（sed） |
| 两稿拼接修复 | 每次2-3章 | 闪莉（kanban） |
| 字数补充 | 每次4章 | 闪莉（kanban） |
| 模板化结尾修复 | 每次2-3章 | 闪莉（kanban） |
| "像"比喻削减 | 全批一次性 | 莉莉（kanban） |
| 大纲偏差修复 | 每次1-2章 | 闪莉（kanban） |
| 章节拆分 | 每次1章 | 直接编辑或闪莉 |

### 方案M-章节拆分工作流

**拆分原则**：
1. **先扩充，再拆分**：如果当前字数不够拆分（如5000字想拆成2×4500字），先扩充到目标总字数
2. **找自然分割点**：在场景转换、情节转换、情感转换处拆分
3. **每章≥4500字**：拆分后每章必须达标

**拆分流程**：
```
Step 1: 分析章节结构
  - 读取完整内容
  - 识别关键节点（场景转换、情节转折）
  - 统计各段落字数

Step 2: 确定拆分点
  - 优先选择场景转换处（如"旧船坞区的竖井旁边"）
  - 其次选择情节转换处（如"仪式是——喂养"）
  - 最后选择情感转换处（如"杰克闭上了眼睛"）

Step 3: 扩充内容（如需要）
  - 如果当前字数不够拆分，先扩充
  - 扩充方向：环境描写、角色互动、情感细节
  - 扩充后总字数≥目标（如2×4500=9000字）

Step 4: 执行拆分
  - 备份原文件（cp 原文件 原文件.bak）
  - 创建上半部分文件（head -N 原文件 > 上半部分.md）
  - 创建下半部分文件（tail -n +N+1 原文件 > 下半部分.md）
  - 更新标题（sed -i '' '1s/旧标题/新标题/'）

Step 5: 验证
  - 每章字数≥4500字
  - 情节完整（无删除）
  - 角色一致（无改变）
```

**拆分点选择优先级**：
1. **场景转换**（最佳）：如"旧船坞区的竖井旁边"
2. **情节转换**（次佳）：如"仪式是——喂养"
3. **情感转换**（可用）：如"杰克闭上了眼睛"

**拆分后文件命名**：
- 上半部分：`第XXX章_章名（上）.md`
- 下半部分：`第XXX+1章_章名（下）.md`
- 原第XXX+1章改名为：`第XXX+2章_原章名.md`

### Token消耗分析

**直接编辑 vs kanban任务效率对比**：

| 操作 | 直接编辑 | kanban任务 | 节省 |
|------|---------|-----------|------|
| sed替换禁用词（28次） | 1分钟 | 5-10分钟 | 80-90% |
| 压缩章节（2000字） | 5分钟 | 10-15分钟 | 50-67% |
| 削减比喻（60次） | - | 3分钟（莉莉） | - |

**关键发现**：
1. **简单批量操作直接编辑更快**：sed替换、字数压缩等操作，直接编辑比创建kanban任务快5-10倍
2. **复杂判断任务用kanban**：像比喻削减需要逐章判断保留哪些，适合莉莉执行
3. **拆分任务可以混合**：简单拆分（head/tail）直接编辑，复杂拆分（需扩充）用kanban

## 经验教训

1. **直接编辑适合简单操作**：sed替换、字数压缩等，不要创建kanban任务
2. **kanban任务适合复杂修改**：需要上下文理解的修改，交给闪莉/莉莉
3. **拆分前先扩充**：字数不够拆分时，先扩充到目标总字数
4. **找自然分割点**：场景转换 > 情节转换 > 情感转换
5. **修改后必须审核**：修改可能引入新问题（如"像"比喻从79→135次）
6. **莉莉效率极高**：像比喻削减194秒完成118次削减
7. **冰哥喜欢直接了当**：简单操作不要创建任务，直接做
