# 闪莉自检模式（Self-Check Pattern）

## 适用场景
当闪莉写完大纲/正文后，需要与之前的版本做一致性校验时使用。

## 触发条件
- 冰哥说"让闪莉自己审核一下"
- 大纲有多个版本需要合并/整合
- 写完后需要验证与旧版的一致性

## 流程

### 1. 在看板任务中追加自检要求
```bash
hermes kanban comment <task_id> "## 追加自检要求
写完后，请自检以下两个文件的内容一致性：
1. **你刚写的文件**：<新文件路径>
2. **之前莉莉丝写的版本**：<旧文件路径>

### 自检维度
- 核心剧情点是否全部覆盖
- 关键设定是否一致
- 角色名是否统一
- 用户要求的扩充内容是否全部包含
- 章节规划是否符合要求

### 输出
在文件末尾添加「自检报告」章节：
- ✅ 一致的项目
- ❌ 不一致的项目（标注差异）
- ⚠️ 你的版本新增了哪些内容

以新版为准，但标注差异。"
```

### 2. 自检维度清单
| 维度 | 检查内容 |
|------|---------|
| 剧情覆盖 | 12个核心剧情点是否全部出现 |
| 设定一致 | 三扇门总结/角色关系/能力设定是否与旧版一致 |
| 角色名 | 去姓/全名是否统一 |
| 扩充维度 | A-F六个维度是否全部包含 |
| 章节规划 | 总章节数/每章字数是否符合要求 |
| 新增内容 | 新版比旧版多了什么（标注差异） |

### 3. 注意事项
- 自检以新版为准（因为更新更完整）
- 差异部分需要标注，方便用户快速定位
- 如果发现旧版有而新版没有的内容，需要确认是故意删除还是遗漏
