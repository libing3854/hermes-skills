# kanban任务Token优化指南

> 基于《我在深渊开事务所》第三卷vs第四卷+第七批vs第八批的实战对比分析，找出token消耗过多的根源并提供优化方案。
> 
> 📌 **v3更新（2026-06-09）**：新增字数标准变更、"仿佛"禁用词、修改任务验证循环陷阱

## 字数标准（冰哥确认 2026-06-09）

**目标字数**：4500-5000字/章
**底线**：≥4500字（低于4500字必须补充）
**上限**：无硬性上限，但超过8000字需要拆分

与之前5000字标准的区别：
- 之前：每章≥5000字（硬性要求）
- 现在：4500-5000字为正常范围，≥4500字即可

## 禁用词扩展（2026-06-09 新增）

除原有禁用词外，莉莉审核发现"仿佛"也是高频AI词：

| 禁用词 | 问题 | 替换方案 |
|--------|------|---------|
| 仿佛 | 28次失控（218章14次最严重） | 删除/替换为"如/如同/似" |
| 深吸一口气 | 反复出现 | 替换为"他吸了一口冷空气" |
| 嘴角微微上翘 | 跨章模板 | 替换为具体表情描写 |

**"仿佛"替换策略**：
- 约40-50%可直接删除（"仿佛有什么东西在催促他"→"有什么东西在催促他"）
- 约20-30%可替换为"如/如同/似"（"仿佛心跳"→"如心跳"）
- 约20-30%需要重新组织句子结构

## 修改任务验证循环陷阱（2026-06-09 新增）

**问题**：即使任务body中明确写了"不要做任何验证"，闪莉仍然会在修改任务中执行验证循环。

**症状**：
- 字数验证执行8次
- 禁用词扫描5次
- 模板检查6次
- 总计消耗19次迭代

**根本原因**：闪莉的"完美主义"倾向——写完后习惯性地验证质量。

**解决方案**：
1. 写作任务body中**不要包含任何验证步骤的说明**（即使是"不要做"也不行，因为闪莉会理解为"需要做但不要做"）
2. 验证工作**100%由莉莉负责**
3. 修改任务只包含修改指令，不包含验证指令

**任务body模板（修改任务）**：
```
## 修改任务

### 修改内容
[具体修改指令]

### 文件路径
[文件路径]

### ⚠️ 重要
- 只执行修改，不要验证修改结果
- 修改完成后立即输出总结报告
- 验证工作由莉莉专门负责
```

## 问题根源

### 1. 两稿拼接（P0）
- 症状：同一章节存在两个版本的内容
- 根因：写作prompt缺乏防拼接约束
- 影响：实际有效内容只有标称字数的60-70%

### 2. 模板化结尾泛滥（P1）
- 症状："帮帮我+赫兹"、"三百公里外"等模式反复出现
- 根因：缺乏反模板词典约束
- 影响：读者体验极差，触发番茄平台"水文"红线

### 3. 修改任务Crash螺旋（P0）
- 症状：修改任务频繁crash，迭代预算耗尽
- 根因：修改任务未拆分，单次任务处理多个问题
- 影响：任务无法完成，浪费大量token

### 4. 任务body过长（P0）
- 症状：iteration budget exhausted (90/90)，触发超时
- 根因：body包含过多预读要求、详细大纲、执行步骤
- 影响：闪莉在90次迭代内无法完成读取+写作，导致超时重跑

### 5. 预读要求过多（P0）
- 症状：闪莉读取前20章+第三卷5章+大纲+ai注意事项+角色设定，消耗大量迭代
- 根因：担心上下文不足，过度预读
- 影响：迭代预算耗尽，任务超时

## 优化方案

### 方案A-防拼接约束（P0）
在写作任务body中明确添加"禁止两稿拼接"的约束。

### 方案B-修改任务拆分（P0）
按问题类型拆分修改任务，每次只处理2-4章的单一问题。

### 方案C-反模板词典（P1）
在任务body中列出禁止使用的模板化短语。

### 方案D-任务body精简（P0）
将任务body从229行精简到80-100行，减少input tokens。

**精简原则**：
1. 删除重复说明（闪莉知道怎么做）
2. 删除审核流程（审核由莉莉执行）
3. 精简预读要求（只保留上一章+大纲+前5章标题）
4. 精简角色规范（只保留本章涉及的角色）
5. 保留核心信息（前情提要、大纲、写作要求、文件路径）

### 方案E-预读范围优化（P0）
将预读要求从6类文件精简到2-3类文件。

**优化后**：
- 上一章（精读）
- 大纲（本批次对应章节）
- 前5章标题（跳读）

### 方案F-质量验证分离（P0）
把质量验证从写作任务中分离出来，交给莉莉专门负责。

**写作任务（闪莉）**：
- 前情提要 + 大纲 + 写作要求
- 写完后输出总结，不做验证
- 任务body：60-80行

**验证任务（莉莉）**：
- 字数验证（1次）
- 禁用词扫描（1次）
- 模板检查（1次）
- 大纲一致性检查（1次）
- 重复段落检查（1次）
- 输出验证报告
- 任务body：100-120行

### 方案G-章节拆分流程
当章节字数超标（>8000字）需要拆分时：

1. 分析章节结构，识别关键节点
2. 确定拆分点（优先场景转换处）
3. 如当前字数不够拆分，先扩充到目标总字数
4. 执行拆分：备份→创建两个文件→更新标题
5. 验证：每章字数≥4500字，情节完整

### 方案H-莉莉执行高频词削减
高频词削减（如"像"比喻）适合交给莉莉：
- 效率极高（194秒完成，削减率87%）
- 每章保留1-2个最精彩比喻
- 闪莉更适合写正文和扩写

### 方案I-修改任务按问题类型拆分（2026-06-11 更新）
修改任务应按问题类型拆分：
- 两稿拼接修复 → 闪莉(Agnes 2.0 Flash)
- 字数补充 → 闪莉(Agnes 2.0 Flash)
- 高频词削减 → 莉莉
- 大纲偏差修复 → 闪莉(Agnes 2.0 Flash)
- 质量审核 → 莉莉

**标准修改Agent**：Agnes 2.0 Flash（`--assignee shanli-agnes20flash`），A/B测试验证其修改更精准、更快、文笔更自然。修改后文件输出到 `正文_agnes/` 目录，冰哥确认后合入 `正文/`。

## 验证方法

### "像"比喻密度检查
```bash
grep -c "像" 文件.md
# 目标：每章 ≤ 15次
```

### "某种"密度检查
```bash
grep -c "某种" 文件.md
# 目标：每章 ≤ 1次
```

### "仿佛"密度检查
```bash
grep -c "仿佛" 文件.md
# 目标：每章 0次（全部替换）
```

### 任务body长度检查
```bash
wc -l 任务body.md
# 目标：80-100行，最大不超过150行
```
