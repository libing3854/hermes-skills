# 章节压缩优化方法论

将已有章节压缩到目标字数范围（如4500-5500字）的工作流。

---

## 触发场景

- 用户说"压缩第X章"、"优化字数到X字"、"精简章节"
- 章节字数超标（>6000字）需要压缩到标准范围
- 批量优化多章字数（如"优化压缩第235-244章"）

---

## 字数统计方法

```bash
# 统计字符数（含标点、换行、标题）
wc -m 文件.md

# 对应关系：
# - 文件大小(bytes) / ~2.5 ≈ 字符数（中文文本粗估）
# - wc -m 统计所有Unicode字符，含markdown标题、换行符
# - 纯中文正文字符数 ≈ wc -m结果 × 0.85（去掉标题/换行/空行）
```

**目标字数参考**：
| 场景 | 目标范围 | 说明 |
|------|---------|------|
| 番茄标准章节 | 4500-5000字 | 冰哥项目默认 |
| 精简压缩 | 4500-5500字 | 压缩任务常用范围 |
| 最低下限 | 4500字 | 低于此必须补充 |

---

## 迭代压缩工作流

### Step 1：读取原文并分析

1. 读取完整章节内容
2. 用 `wc -m` 获取当前字数
3. 计算需要压缩的比例：`(当前字数 - 目标上限) / 当前字数`
4. 识别可压缩区域（按优先级）：
   - 重复的环境描写（如"盐的味道和铜锈的味道"出现多次）
   - 冗余的技术解释/对话
   - 过度展开的比喻和形容
   - 重复的场景（如同一场景写了两遍）
   - 碎片化短句（可以合并为流畅长句）

### Step 2：写入优化版本

直接用 `write_file` 覆盖原文件。压缩策略：

**高优先级删除（安全删除，不影响剧情）**：
- 重复出现的环境描写（同一气味/景色描写3次以上，保留1-2次）
- 重复的场景（如"六个人一起走"写了两遍，保留一遍）
- 过度的感叹号和省略号
- 冗余的"他说/她说"对话标签

**中优先级压缩（需要改写，保留信息）**：
- 长段技术解释 → 压缩为核心结论
- 多人发言的同质内容 → 合并为1-2人发言
- 详细的过去回忆 → 保留关键人物和事件
- 过度展开的比喻 → 保留最生动的1-2个

**低优先级压缩（谨慎处理）**：
- 核心对话（推动剧情的对话不能删）
- 关键情节点（删除会导致剧情断裂）
- 角色特征描写（删除会削弱人设）

### Step 3：字数验证

```bash
wc -m 优化后的文件.md
```

- 如果字数在目标范围内 → 完成
- 如果字数偏高 → 回到Step 2继续压缩
- 如果字数偏低 → 用 `patch` 补充内容（扩展关键场景/对话）

### Step 4：补充内容（字数不足时）

当压缩过度导致字数偏低时，补充方向：
- 扩展关键对话场景（增加角色互动细节）
- 补充环境描写（仅在场景转换处）
- 增加角色内心活动（用动作展示，不用直接告诉）
- 展开重要的情节点

**补充技巧**：
- 用 `patch` 精确插入，不要重写整个文件
- 每次补充后用 `wc -m` 验证
- 目标是达到范围下限即可，不要过度补充

---

## 批量压缩流程（多章）

当需要压缩多个章节时：

1. **先处理所有章节**：逐章执行Step 1-2，一次性写入所有优化版本
2. **统一验证字数**：批量 `wc -m` 检查所有章节
3. **补充不足的章节**：对字数偏低的章节用 `patch` 补充
4. **生成修改报告**：记录每章的修改内容

**效率提示**：
- 10章以内可以逐章手动处理
- 10章以上建议先写完所有章节，再统一验证和补充
- 避免在单章上反复迭代（每章最多2-3轮调整）

## 压缩技巧清单

### 删除类（安全删除）
| 模式 | 示例 | 处理 |
|------|------|------|
| 重复环境描写 | "盐的味道和铜锈的味道"×4 | 保留1-2次 |
| 重复场景 | "六人一起走"写了两遍 | 保留一遍 |
| 冗余感叹 | "!!!""..."过多 | 适度保留 |
| 过度对话标签 | 每句都有"他说" | 删除50%+ |
| 重复比喻 | "像XXX"多次出现 | 保留最生动的 |

### 改写类（保留信息，压缩表达）
| 模式 | 示例 | 处理 |
|------|------|------|
| 长技术解释 | 3段频率分析 | 压缩为1段核心结论 |
| 多人同质发言 | 5人说类似的话 | 合并为1-2人 |
| 详细过去回忆 | 6人每人100字描述 | 每人保留30-50字 |
| 过度展开比喻 | 5个连续比喻 | 保留2-3个 |
| 碎片化短句 | "他走了。很远。很慢。" | 合并为"他走了很远，很慢" |

### 保留类（不能删）
| 模式 | 原因 |
|------|------|
| 核心对话 | 推动剧情的关键信息 |
| 情节转折点 | 删除会导致剧情断裂 |
| 角色特征 | 删除会削弱人设 |
| 章尾钩子 | 读者留存的关键 |
| 伏笔回收 | 影响后续章节 |

## 修改记录模板

压缩完成后，生成修改报告：

```markdown
## 第XXX章优化记录

**原始字数**：XXXX字 → **优化后**：XXXX字（压缩XX%）

### 主要修改：
1. 删除了重复的XXX描写（原出现X次，保留X次）
2. 压缩了XXX的技术解释（从X段精简为X段）
3. 合并了XXX的碎片化短句
4. 删除了冗余的对话标签
5. 补充了XXX场景的细节（字数偏低时）

### 保留的核心内容：
- XXX对话/场景（关键剧情点）
- XXX描写（角色特征/伏笔）
```

## 常见陷阱

### ❌ 过度压缩
- 删掉核心对话导致剧情断裂
- 删除角色特征描写削弱人设
- 压缩章尾钩子影响读者留存

### ❌ 不验证字数
- 写完就结束，不检查是否达标
- 用估算代替 `wc -m` 精确统计

### ❌ 反复迭代同一章
- 在单章上调整5+轮，浪费时间
- 应该：最多3轮，然后标记"需人工审核"

### ❌ 忽略上下文
- 压缩时删除了与前后章衔接的内容
- 应该：保留与前章结尾和后章开头的衔接点
