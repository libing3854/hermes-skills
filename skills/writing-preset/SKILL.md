# 写作预设（Writing Preset）

看板任务body的标准模板库。复制粘贴到 `hermes kanban create --body` 中即可使用。

**定位：** 本技能提供模板素材，实际写作流程由 story-long-write 驱动。

## 模板1：长篇日更任务

```
### 写作预设（长篇日更）

#### ⚠️ 重要：预读前文要求（必读）
**在开始写作前，必须先读取以下文件作为上下文参考：**

必读文件（按优先级）：
1. 上一章正文（精读）
2. 大纲：[路径]（精读本批次章节）
3. 前5章标题（跳读，了解最近事件）

预读目的：保持角色一致性、情节连贯性、风格一致性、伏笔衔接。

#### 护栏（写完每章后自查）
- [ ] 段落以1-3句为主，有长短交错
- [ ] 心理描写外化为动作（"手在抖"代替"他很紧张"）
- [ ] 对话标签使用频率 ≤30%
- [ ] 禁用词扫描：深吸一口气、眼中闪过、嘴角勾起、仿佛/犹如/宛若、不禁
- [ ] 章尾用动作/场景收尾，不用总结式感慨
- [ ] "像"字比喻 ≤15次/章（超过则削减）
- [ ] "某种" ≤3次/章（超过则替换为具体描述）
- [ ] 禁止模板化短语（帮帮我+赫兹结尾、像心跳像呼吸、不是疼痛是温热、嘴角微微上扬等）

#### 角色对话规范
[从 设定/角色/ 目录读取本章涉及角色的示范对话段落，粘贴在这里]

#### 上下文标注
本章涉及：
- 角色：[列出本章出场角色]
- 地点：[列出本章场景地点]
- 伏笔：[列出本章需回收/推进的伏笔]
请读取以上角色的设定文件和相关伏笔文件。
```

## 使用方法

1. 选择对应场景的模板
2. 把 `[方括号]` 中的内容替换为实际参数
3. 粘贴到 `hermes kanban create --body` 中

## ⚠️ 任务body长度控制（P0 坑，2026-06-09 实战教训）

**问题**：任务body过长（>150行）会导致闪莉iteration budget耗尽（90/90），触发超时。

**根因**：
- body越长，每次迭代读取的input tokens越多
- 预读要求过多（前20章+第三卷5章+大纲+ai注意事项+角色设定）消耗大量迭代
- 闪莉在90次迭代内无法完成读取+写作

**优化策略**：
| 指标 | 当前（问题版） | 目标（优化版） |
|------|---------------|----------------|
| body长度 | 229行 | **80-100行** |
| 预读文件 | 6类 | **2-3类** |
| 运行次数 | 2次（超时1次） | **1次** |
| Token消耗 | 高 | **降低40-50%** |

**精简原则**：
1. **删除重复说明**：闪莉知道怎么做，不需要详细执行步骤
2. **删除审核流程**：审核由莉莉执行，不在写作任务中
3. **精简预读要求**：只保留"上一章+大纲+前5章标题"
4. **精简角色规范**：只保留本章涉及的角色（3-5个）
5. **保留核心信息**：前情提要、大纲、写作要求、文件路径

**示例（优化后）**：
```
## 必读文件（按优先级）
1. 上一章：正文/第217章_共鸣.md
2. 大纲：新第四卷_详细章节大纲_潮港青铜.md（第023-027章）
3. 前5章标题：正文/第213-217章（跳读）

## 本批次大纲
[只保留核心内容要点，每章2-3行]

## 写作要求
[精简版：字数、风格、禁用词、文件路径]
```

## ⚠️ Hermes Skill 系统限制（P0 坑）

Hermes 的 skill 系统是**静态文本加载**，以下能力均不存在：
- **连锁调用** — 加载 writing-preset 不会自动加载 writing-guardrails 等子技能
- **自动注入** — 没有机制能在写作过程中定期插入提醒
- **自动分析** — 没有机制能自动识别章节涉及的角色/地点并加载设定
- **参数传递** — temperature/creativity 等参数无法通过 skill 控制模型行为

**正确做法：** 所有"自动化"意图都落地为**手动操作清单 + 看板任务body模板**。

## ⚠️ 进度汇报必须包含字数（冰哥偏好 2026-06-10）

汇报章节完成状态时，**必须显示每章的实际字数**。格式：
```
第235章: 8,159 字
第236章: 7,973 字
```
不要只显示"已完成"而不报字数。

---

## ⚠️ 字数上限必须明确（2026-06-10 实战教训）

任务body中只写"4500-5000字"时，闪莉实际产出常达到6500-10667字（超出30-97%）。

**正确写法：**「每章4500-5500字，不超过6000字」
**错误写法：**「每章4500-5000字」（没有上限 = 闪莉会自由发挥到8000-10000字）

---

## ⚠️ 进度汇报必须包含字数（冰哥偏好 2026-06-10）

汇报章节完成状态时，**必须显示每章的实际字数**。格式：
```
第235章: 8,159 字
第236章: 7,973 字
```
不要只显示"已完成"而不报字数。字数统计用 `wc -m`（中文字符数），不要用 `wc -c`（字节数）。

**批量统计脚本（推荐）：**
```bash
for i in 235 236 237 238 239; do
  file=$(ls "正文/第${i}章_"*.md 2>/dev/null | head -1)
  if [ -n "$file" ]; then
    chars=$(wc -m < "$file" 2>/dev/null)
    echo "第${i}章: ${chars} 字"
  fi
done
```

## 模板4：高频词削减任务（2026-06-09 新增）

```
### 写作预设（高频词削减）

#### 目标
将全批"像"比喻从X次削减到Y次（每章≤15次）

#### 削减原则
- 每章保留1-2个最精彩的"像"比喻
- 其余用直接描写替换

#### 替换方法
方法A：删除"像"，保留描写
- ❌ "像一只巨大的眼睛"
- ✅ "一只巨大的眼睛"

方法B：改为动词
- ❌ "像被一只手抽走"
- ✅ "被一只手抽走"

方法C：删除比喻
- 如果比喻不服务于情境，直接删除

方法D：改为其他修辞
- ❌ "像一根钢缆"
- ✅ "绷得紧紧的钢缆"

#### 验证
修改后用 grep -o '像' 文件 | wc -l 验证每章数量
```
