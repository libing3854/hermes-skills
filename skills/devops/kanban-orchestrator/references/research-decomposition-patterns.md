# 研究任务分解模式（防崩溃版）

> 发现时间：2026-05-28
> 场景：大型研究项目（100+模块）的看板任务分解

## 适用场景

当研究项目规模庞大（如103个模块、300-500小时工时），需要：
1. 分解为多个≤2小时的看板任务
2. 每个任务有防崩溃策略（分阶段执行，每步保存）
3. 任务之间有依赖关系
4. 支持多条并行轨道

## 防崩溃三阶段框架

每个研究任务的 body 提示词嵌入以下框架：

```
【阶段1-上下文加载】(≤30分钟)
- 读取已有参考文件
- 提取关键概念
- 输出到 [文件名]_草稿.md → 保存

【阶段2-深度研究】(≤60分钟)
- 搜索补充资料（中/英文关键词）
- 逐条整理研究内容
- 追加到草稿 → 保存

【阶段3-整理定稿】(≤30分钟)
- 结构化排版
- 标注引用来源
- 输出最终版 → 保存为 [文件名].md
- 标记任务状态为 ✅
```

### 关键规则
- **每完成一个阶段立即保存中间文件**
- 如果中途中断，从最近的 `_草稿.md` 恢复继续
- 每个阶段独立可重试，不影响已完成阶段
- 草稿文件命名规范：`模块编号_主题_草稿.md`

## 任务分组原则

| 原则 | 说明 |
|------|------|
| ≤2小时/任务 | 防止 token 耗尽和会话超时 |
| 按主题分组 | 同一主题的任务放在同一轨道 |
| 依赖关系清晰 | 前置任务完成后后续任务才能开始 |
| 并行轨道独立 | 不同轨道的任务可同时执行 |
| 精华版标注 | 压缩过度的任务明确标注"产出为目录级笔记" |

## 依赖关系管理

### 声明依赖
```bash
hermes kanban create "任务名" \
  --parent <前置任务ID> \
  --assignee default \
  --max-runtime 2h
```

### 跨阶段依赖
当阶段2的任务依赖阶段1的产物时：
- 在任务 body 中明确标注要读取的前置产物路径
- 在依赖声明中包含前置任务ID
- 在并行策略说明中标注阻塞点

### 示例
```
阶段1轨道B: T0108 → T0109 → T0110（串行）
阶段2轨道A: T0201-T0208（大部分可并行）
阶段2跨阶段: T0205 依赖 T0109（需等阶段1完成）
```

## 输出文件命名

```
详解/
├── 01-02A-混沌领域结构.md      # 阶段1产物
├── 01-02B-混沌与现实交互.md    # 阶段1产物
├── 01-02C-混沌腐化.md          # 阶段1产物
├── 01-03A-八风来源与机制.md    # 阶段1产物
├── 03-01A-道生万物.md          # 阶段2产物
├── 03-02C-五行八风对照.md      # 阶段2产物（依赖阶段1）
└── 99-总索引.md                # 最终汇总
```

### 命名规范
- 编号前缀：`XX-YYY-`（XX=编，YYY=模块）
- 后缀区分：`A/B/C` 表示同模块的不同部分
- 避免编号冲突：插入新模块后需更新后续编号

## 审核流程（大莉M+大莉D双通道）

### 设计阶段
1. **大莉M** 设计任务分配方案（分组、依赖、body提示词）
2. **大莉D** 审核方案（检查依赖完整性、时间合理性、遗漏模块）

### 执行阶段
1. 按依赖顺序创建看板任务
2. 每个任务完成后验证产出文件
3. 阶段完成后汇总检查

### 修复循环
```
大莉D发现问题 → 修复 → 大莉M复核 → 通过 → 继续
```
