# 研究类看板任务设计模式

> 来源：2026-05-28 战锤×道教世界观研究项目实战经验

## 核心教训：读+写必须合并为一个任务

**错误做法**：拆成两个独立任务
```
任务A（索引）→ 生成索引文件 → done
任务B（读写）→ 被要求"读取索引并总结" → 失败（无法读取任务A的输出）
```

**原因**：看板任务是独立执行的，任务B的body里写了要读取文件，但实际执行时可能没有正确执行文件读取，或者文件路径不匹配。

**正确做法**：合并为一个任务
```
任务（索引+读写）→ 先读索引 → 搜索原始资料 → 写总结 → done
```

## 防崩溃设计：分阶段执行+每步保存

适用于耗时较长的研究任务（预估 >30分钟）。

### 原则
1. **每完成一个阶段立即写入文件**，不要等最后一起写
2. **每个文件写入后验证**：用 `ls -la` 确认文件存在且大小合理（建议 ≥500 字节）
3. **失败跳过**：某个阶段失败就跳过，已完成的文件不会丢失
4. **超时截断**：每个阶段设时间上限，超时就保存当前进度进入下一阶段

### 模板结构
```markdown
## 阶段1：读取现有资料（X分钟）
读取以下文件...
完成后保存：写入 `详解/01-xxx.md`

## 阶段2：主题A研究（X分钟）
搜索关键词：...
完成后立即保存：写入 `详解/02-xxx.md`

## 阶段3：主题B研究（X分钟）
...

## 阶段N：综合分析（X分钟）
⚠️ 前置检查：确认前序文件全部存在且非空
完成后立即保存：写入 `详解/0N-xxx.md`
```

### 关键约束
- **依赖检查**：综合分析等依赖前序阶段的任务，必须在开头检查前置文件是否存在
- **文件命名统一**：避免多个文件用相同前缀（如都叫 `00-`）
- **搜索关键词去重**：检查各阶段关键词是否有重叠，避免重复工作
- **时间分配现实**：AI agent 单次会话 token 有限，总时长控制在 2 小时内为宜

## 任务body由大莉编写

复杂研究任务的body/提示词让大莉M或大莉D来写，质量更高。大莉擅长：
- 设计完整的研究结构
- 列出精确的搜索关键词
- 规划合理的时间分配
- 识别潜在的逻辑冲突和遗漏

## 搜索策略建议

- **限定来源**：战锤搜索加 `site:lexicanum.com` 或 `site:warhammerfantasy.fandom.com`
- **中英双语**：战锤用英文关键词，道教用中文关键词
- **每组关键词**：调用 `web_search` 获取前 5 条结果，对重要结果调用 `web_extract` 提取全文
- **输出控制**：每个阶段输出 3000~8000 字

## 多Agent审核循环：大莉M写 → 大莉D审 → 修复 → 大莉D复核

对于需要高质量产出的研究/设计项目，采用双通道审核流程：

### 流程
```
1. 大莉M编写索引/方案（深度推理，结构化输出）
2. 大莉D审核（发现问题清单，给出修改建议）
3. 莉莉丝/闪莉根据审核意见修复
4. 大莉D复核修复结果（确认通过/仍有问题）
5. 必要时回到步骤3循环
```

### 适用场景
- 大型研究索引框架设计（100+模块）
- 复杂任务分配方案设计
- 世界观/架构设计文档

### 关键点
- 大莉M擅长**深度推理和结构化设计**，适合编写复杂方案
- 大莉D擅长**细节审查和一致性检查**，适合找bug和逻辑冲突
- 两者的审查视角不同（M偏宏观逻辑，D偏微观细节），互补效果好
- 审核发现问题后，修复者不一定是原作者，可以是莉莉丝或闪莉
- 最终复核必须由审核者（大莉D）确认，不能自审自批

### 实战案例（2026-05-28）
战锤×道教世界观项目中：
1. 大莉M设计了94模块的索引框架 → 大莉D审核发现22处优先级矛盾+3对文件命名冲突
2. 修复后大莉D复核 → 发现1个新问题（产出文件编号冲突）→ 再次修复
3. 大莉M最终完整审核 → 通过
4. 大莉M设计40个看板任务分配方案 → 大莉D审核发现依赖声明不完整+跨阶段阻塞未标注
5. 修复后大莉D复核 → 通过
