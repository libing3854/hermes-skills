# 小说大纲连贯性检查技能

## 目标

检查长篇小说多卷大纲的连贯性，识别并修复跨卷角色状态、时间线、伏笔回收等一致性问题。

## 触发条件

- 用户要求检查小说大纲的连贯性
- 用户修改了某一卷大纲，需要确保与其他卷保持一致
- 用户合并或拆分卷次时需要重新调整

## 核心检查维度

### 1. 角色状态一致性

**检查要点：**
- 角色在不同卷中的存活/死亡状态
- 角色能力成长轨迹是否合理
- 角色关系变化是否连贯
- 角色性格发展是否符合弧线

**常见问题：**
- 角色在某一卷牺牲，但后续卷仍作为活跃角色出现
- 角色能力突然增强或减弱，缺乏铺垫
- 角色关系跳跃式变化，缺少过渡

**修改策略：**
- 若角色在前卷牺牲，后续卷可：
  - 完全删除该角色相关内容
  - 改为回忆/遗物形式保留
  - 通过其他角色转述其影响

### 2. 时间线一致性

**检查要点：**
- 各卷之间的时间跨度
- 事件发生的先后顺序
- 年龄/日期等具体时间信息

**常见问题：**
- 时间线跳跃导致逻辑矛盾
- 年龄与事件发生时间不符
- 多个事件同时发生但描述为先后

**修改策略：**
- 建立统一的时间线表格
- 在大纲中标注关键时间节点
- 检查章节编号与时间的对应关系

### 3. 世界观一致性

**检查要点：**
- 设定规则是否前后一致
- 新增设定是否与旧设定冲突
- 术语使用是否统一

**常见问题：**
- 能力体系规则矛盾
- 组织/势力设定不一致
- 道具/物品属性前后不符

**修改策略：**
- 建立世界观设定文档
- 新增设定时检查是否与旧设定冲突
- 统一术语和命名

### 4. 伏笔回收一致性

**检查要点：**
- 前卷埋下的伏笔是否在后卷回收
- 伏笔回收是否自然合理
- 是否有遗漏的伏笔

**常见问题：**
- 重要伏笔被遗忘
- 伏笔回收过于突兀
- 多个伏笔同时回收导致混乱

**修改策略：**
- 建立伏笔清单，标注回收卷次
- 检查每个伏笔的回收是否合理
- 调整伏笔回收的节奏

## 工作流程

### 第一阶段：信息收集

1. **读取所有相关卷次大纲**
   - 获取完整的故事脉络
   - 记录关键事件和角色状态

2. **建立角色状态表**
   - 列出所有重要角色
   - 记录每卷结束时的状态
   - 标注状态变化的关键节点

3. **建立时间线表格**
   - 标注每卷的时间跨度
   - 记录关键事件的时间点

### 第二阶段：连贯性检查

1. **逐卷对比检查**
   - 检查角色状态变化
   - 检查时间线逻辑
   - 检查世界观设定

2. **跨卷整体检查**
   - 检查伏笔回收情况
   - 检查主题一致性
   - 检查风格一致性

3. **生成问题清单**
   - 列出所有发现的问题
   - 按严重程度分类（必须修改/建议修改/可接受）
   - 提供修改建议

### 第三阶段：修改执行

1. **与用户确认修改方案**
   - 展示问题清单和修改建议
   - 等待用户确认
   - 根据反馈调整方案

2. **执行修改**
   - 按优先级逐步修改
   - 每次修改后检查是否引入新问题
   - 保持修改记录

3. **最终验证**
   - 重新检查修改后的内容
   - 确保所有问题已解决
   - 确认修改未引入新问题

## 常见陷阱

### 1. 角色状态矛盾
- **现象**：角色在某一卷牺牲，但后续卷仍作为活跃角色出现
- **原因**：修改某一卷时未考虑对其他卷的影响
- **解决**：建立角色状态跟踪表，修改时同步更新

### 2. 跨卷角色移除不彻底
- **现象**：角色在前卷牺牲，只修改了紧邻的下一卷，但更后面的卷仍残留该角色
- **原因**：只检查了"下一本"而非"所有后续卷"
- **解决（系统性检查清单）**：当角色牺牲后，逐卷检查以下位置：
  - [ ] 卷首的「已有队友/角色列表」
  - [ ] 卷级情绪弧线表格中的核心事件
  - [ ] 团队当前状态表
  - [ ] 各情节点中的具体参与（对话、战斗分工、探查队组成）
  - [ ] 卷末的「各队友结局」章节
  - [ ] 卷末代价/状态总结表
  - [ ] 能力成长轨迹表（如果该角色有能力展示）
  - [ ] 章节正文中的回忆/遗物引用（这些可以保留，但要标注为"回忆"）
- **修改原则**：死亡角色在后续卷中可保留为「回忆提及」「遗物」「精神遗产」，但不能作为活跃参与者出现

### 3. 章节编号陷阱
- **现象**：在早期卷章节总数未确定时，给后期卷写死了具体章节编号
- **原因**：假设了前面卷的章节数，但实际写作时可能变化
- **解决**：
  - 用**相对位置**代替具体编号（如"前1/7"、"中间"、"第一部分"、"第二部分"）
  - 关键数据表中写"约55-70章"的弹性范围，不写死
  - 等前面卷实际写完确定章节数后，再回填具体编号

### 4. 新卷插入后的"起始状态"未更新
- **现象**：在已有大纲中间插入新卷后，最终卷的"起始状态"仍引用旧的前序卷
- **原因**：插入新卷后，最终卷的前序卷变了，但起始状态描述没有同步更新
- **解决**：插入新卷后，最终卷必须更新：
  - [ ] 起始状态中的"前序卷名称"
  - [ ] 鉴定能力/角色能力的当前描述（累加新卷的成长）
  - [ ] 团队成员状态（新卷引入的队友/变化）
  - [ ] 城市/世界状态（新卷带来的变化）
  - [ ] 封印/倒计时等全局状态的累计值

### 5. 时间线混乱
- **现象**：事件发生时间与描述不符
- **原因**：多卷并行写作时时间管理不当
- **解决**：建立统一时间线，每次修改后检查

### 6. 伏笔遗忘
- **现象**：重要伏笔被遗忘未回收
- **原因**：伏笔数量多，缺乏系统管理
- **解决**：建立伏笔清单，定期检查回收情况

### 7. 设定冲突
- **现象**：新增设定与旧设定矛盾
- **原因**：修改时未全面检查旧设定
- **解决**：建立世界观设定文档，新增时对照检查

### 8. 跨卷大纲角色定义矛盾（高频）
- **现象**：不同卷的大纲对同一角色的定义不同。例如第四卷大纲写"诺亚=萝莎的丈夫"，第五卷大纲写"诺亚=萝莎的弟弟"
- **原因**：不同卷的大纲由不同批次写作生成，缺乏跨卷一致性检查
- **解决原则**：**"以写完的为准"** — 已完成正文的卷次设定优先于未写的大纲
- **检查方法**：写作新卷前，grep搜索该角色在前几卷正文中的所有出现，确认关系设定
- **修改方法**：修改未写卷的大纲，而非修改已定稿的正文
- **坑**：不要试图同时改两边，会越改越乱。先定一方，再改另一方

## 最佳实践

1. **定期检查**：每完成一卷后进行连贯性检查
2. **文档化**：建立角色状态表、时间线、伏笔清单等文档
3. **版本控制**：使用Git管理大纲修改历史
4. **用户确认**：重要修改前与用户确认
5. **渐进式修改**：优先修改必须修改的问题，逐步优化
