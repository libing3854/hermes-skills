## 一、核心工作模式：组合代理 🤜🤛

**核心思想**：高阶代理带着低阶代理一起干。不是只派一个人，而是组队上。

### 调用方式

```bash
# ── 优先调用 ChatAnywhere（免费 Key） ──────────────────────────────
# 冰哥的 chatanywhere/GPT_API_free 免费 Key，每日 30 次/模型
# 限额耗尽 → 自动降级到 DeepSeek 官方 API

# 莉莉（deepseek-v4-flash）— ChatAnywhere 优先
delegate_task(tasks=[{goal: "审核任务", model: {model: "deepseek-v4-flash", provider: "custom:ChatAnywhere Flash"}}])
# 限额耗尽后备方案（莉莉丝自动检测并重试）：
delegate_task(tasks=[{goal: "审核任务", model: {model: "deepseek-v4-flash", provider: "deepseek"}}])

# 大莉M（mimo-v2.5-pro）— 核弹首选
delegate_dalim()  # 切换到大莉M → delegate_task 执行

# 大莉D（deepseek-v4-pro）— ChatAnywhere 优先
delegate_task(tasks=[{goal: "深度任务", model: {model: "deepseek-v4-pro", provider: "custom:ChatAnywhere Pro"}}])
# 限额耗尽后备方案：
delegate_task(tasks=[{goal: "深度任务", model: {model: "deepseek-v4-pro", provider: "deepseek"}}])

# 小莉 — 本地处理（oMLX 默认 Huihui-Qwen3.5-4B）
terminal(background=true, notify_on_complete=true, command="xiaoli chat -q '指令'")

# 闪莉mimi — mimi 分类小模型竞速（NVIDIA/OpenRouter/Google，由 Ping 排名选最快）
delegate_task(tasks=[{goal: "轻度任务", model: {model: "deepseek-v4-flash"}}])

# 闪莉 — 三 Provider 竞速（日常主力）
delegate_task(tasks=[{goal: "日常任务", model: {model: "deepseek-v4-flash"}}])
```

### 子代理输出规范

- 小莉：文件直接写入冰哥指定目录，输出路径需向我汇报
- 闪莉mimi / 闪莉 / 大莉M / 大莉D：`delegate_task` 返回的 `summary` 即输出
- 🧐 **莉莉**：返回审核报告（问题列表+修改建议），审核通过则放行，不通过则附修改建议返修
- 多子代理并行时，最终汇总到我手里整合
- 中间产物用完即删，不留垃圾文件

### 六种组合模式

#### 模式一：🏠 小莉 solo

> **场景**：纯本地操作，不需要任何联网

```
莉莉丝 ──派发──▶ 🏠 小莉（后台跑）
             └── 校验结果 ▶ 交付冰哥
```

**示例**：批量重命名文件、按模板生成文档、本地数据处理

#### 模式二：🐣 闪莉mimi（小莉替补）

> **场景**：高峰期 NVIDIA API 慢，或小莉正在执行其他任务

```
莉莉丝 ──派发──▶ 🐣 闪莉mimi（mimi分类小模型竞速）
             ├── 3个最快的mimi模型并发
             └── 全失败 → 🏠 小莉本地兜底
```

**示例**：翻译一段文字、简单内容生成、安全审核

#### 模式三：⚡ 闪莉 + 🏠 小莉

> **场景**：需要联网搜集信息 + 本地处理

```
莉莉丝 ──分派──▶ ⚡ 闪莉（NVIDIA多模型竞速/搜索）
             └── 🏠 小莉（后台处理本地文件）
             ──并行──▶ 莉莉丝汇总校验 ▶ 交付冰哥

闪莉内部：
  多个闪莉并行执行 → 任务类型判断 → 选候选池 → 3模型并发竞速 → 最快返回
  全失败 → deepseek-v4-flash 兜底 → 仍失败 → 🚀 大莉核弹兜底
```

**示例**：搜索最新资讯并生成本地报告 → 闪莉搜内容，小莉写文件

#### 模式四：⚡ 闪莉 + 🐣 闪莉mimi

> **场景**：需要深度分析 + 轻量处理，不用 Pro 模型省钱

```
莉莉丝 ──分派──▶ ⚡ 闪莉（NVIDIA多模型深度竞速）
             └── 🐣 闪莉mimi（mimi分类小模型轻量处理）
             ──并行──▶ 莉莉丝汇总校验 ▶ 交付冰哥
```

**示例**：分析行业趋势 → 闪莉用强模型做深度分析，闪莉mimi做数据整理

#### 模式五：🚀 大莉 + ⚡ 闪莉

> **场景**：高难度任务，需要深度分析 + 多源资料搜集（大莉核弹出场）

```
莉莉丝 ──分派──▶ 🚀 大莉（深度推理、核心逻辑）
             └── ⚡ 闪莉（多路搜索、资料验证）
             ──两者并行──▶ 大莉汇总合并 ▶ 莉莉丝终检 ▶ 交付冰哥
```

**示例**：做行业研究报告 → 大莉分析趋势，闪莉搜各家公司数据

#### 模式六：🚀 大莉 + ⚡ 闪莉 + 🏠 小莉（全家桶）

> **场景**：大型复杂项目，三层联动

```
莉莉丝 ──分派──▶ 🚀 大莉（核心推理、架构设计）
             ├── ⚡ 闪莉（多路并行搜索、资料整理）
             └── 🏠 小莉（本地文件处理、代码编写）
             ──三者并行──▶ 大莉汇总 ▶ 莉莉丝终检 ▶ 交付冰哥
```

**示例**：构建完整研究项目 → 大莉定框架，闪莉搜资料，小莉写代码

### 组合速查

| 任务特点 | 最优组合 | ❌ 别用（浪费） | 典型场景 |
|---------|---------|---------------|---------|
| 纯本地、无需联网 | 🏠 小莉 solo | 全家桶、大莉 | 文件批量处理、代码生成 |
| 高峰期轻量任务 | 🐣 闪莉mimi | 大莉出场 | 翻译、简单生成 |
| 日常搜索+本地整理 | ⚡ 闪莉 + 🏠 小莉 | 大莉出场 | 新闻搜集+写报告 |
| 深度分析+轻量整理 | ⚡ 闪莉 + 🐣 闪莉mimi | 大莉+小莉 | 行业分析+数据整理 |
| 高难度+多源资料 | 🚀 大莉 + ⚡ 闪莉 | 小莉 solo（干不了） | 行业研究、竞品分析 |
| 大型项目全流程 | 🚀 大莉 + ⚡ 闪莉 + 🏠 小莉 | 少派一个就会缺腿 | 完整研究项目 |

### 并行执行规范

1. **真并行**：子代理间互不依赖 → 同时启动
2. **流水线**：A 的输出是 B 的输入 → A 先启动，拿到结果后立即启动 B
3. **多个闪莉实例并行**，解决连接不稳定
4. **小莉总是后台跑**（`background=true`），不阻塞主流程
5. **闪莉内部自动竞速**，我只需要指定任务类型
6. 同时 `terminal(background=true)` 启动小莉

## 二、闪莉竞速机制（三 Provider）🏁

### 工作原理

闪莉接任务后，不是等一个模型慢慢响应，而是**多个闪莉并行 + 同组多模型并发竞速**：

```
接任务 → 多个闪莉实例并行（解决网络不稳定）
            ↓
    每个闪莉：判断任务类型 → 选候选池 → 3模型并发
            ↓
        🏁 谁先回来就用谁的
        其余线程自动丢弃
            ↓
    全部失败 → deepseek-v4-flash 兜底
            ↓
    仍失败 → 🚀 大莉核弹兜底
```

### 竞速分组

| 组 | 候选池 | 并发数 | 场景 |
|:--:|--------|:------:|------|
| ⚡ **闪电组** | mimi 分类（NVIDIA 18 + OpenRouter 5 + Google 2） | 3 | 简单闲聊、高峰期 |
| 🚀 **标准组** | light 分类（NVIDIA 33 + OpenRouter 7 + Google 5） | 3 | 日常对话、搜索 |
| 🖼️ **视觉组** | vision 分类（OpenRouter 1 + Google 1） | 2 | 看图/网页/视频 |
| 🧠 **深度组** | deep 分类（NVIDIA 14 + OpenRouter 4 + Google 1） | 3 | 深度推理 |

### 波峰波谷感知

闪莉根据当前 API 负载等级调整策略：

| 负载 | 策略 |
|:----:|------|
| 🌙 **低谷期** | 正常竞速，大模型放心用 |
| ☀️ **正常** | 按任务类型正常选组 |
| 🚥 **高峰期** | 只用 mimi 组小模型竞速 |
| ⚠️ **异常尖峰** | 放弃 NVIDIA，直接切小莉本地 |

### 兜底链（完整）

**闪莉降级链：**
```
⚡ 闪莉竞速（3 Provider 并发） → 全失败 → deepseek-v4-flash 兜底
                ↓ 仍失败
         🚀 大莉（核弹模型）最终兜底
```

**闪莉mimi降级链：**
```
🐣 闪莉mimi竞速（mimi 分类小模型并发） → 全失败 → 🏠 小莉 本地处理
```

## 三、任务分段原则 📋

### 接任务三步走

```
1. 自评复杂度（⭐1-5）
   ⭐ 简单的 → 我自己直接回答，不派子代理
   ⭐⭐⭐ 以上 → 启动组合代理模式

2. 匹配组合模式 → 用决策树选最优模式

3. 预估耗时 → 心里有个数，太长的可以跟冰哥说一声
```

### 决策树

```
这个任务需要什么？
├── 💬 简单问答/轻量任务？      → 我直接回答，不派子代理
├── 🧠 需要深度推理/复杂判断？  → 尝试闪莉（省钱）→ 失败 → 大莉（核弹）
├── 🌐 需要联网搜索/整理？      → 闪莉（三 Provider 竞速）
├── 🖼️ 需要看图/看网页/看视频？→ **必须派闪莉**（我自身视觉取决于基座模型），先查 ranking.json 选延迟最低的视觉模型
├── 💻 需要本地文件操作/编写？  → 小莉
├── 🔍 不需要思考？             → 我自己顺手做
└── ❓ 不确定？                 → 问冰哥

附加判断：
    高峰期（API慢）？ → 闪莉mimi 或 小莉
    低谷期（API快）？ → 闪莉 正常竞速
    闪莉全失败？     → 大莉核弹出场
```

### 什么时候需要审核

```
任务完成
├── ⭐ 简单任务（日常问答、轻量操作）
│   └── 我自己交付，无需审核
├── ⭐⭐⭐ 普通任务（搜索/写代码/生成HTML等）
│   └── 派 🧐 莉莉（deepseek-v4-flash）审核 → 通过则交付
├── ⭐⭐⭐⭐⭐ 重任务（研究报告/复杂项目/关键决策）
│   └── 派 🚀 大莉M / 大莉D 审核 → 通过则交付
└── 审核不通过 → 自行修正 → 重新送审 → 直到通过
```

## 四、定时任务执行策略 ⏰

所有定时任务统一采用 **「我执行 + 审核兜底」** 模式：

```
莉莉丝（当前会话模型）执行
   ↓ 完成任务
莉莉丝自行校验 → 确认无误 → 交付
   ↓ 复杂任务
🧐 莉莉（deepseek-v4-flash）审核 → 通过则交付
```

### 模型选择

**模型选择由 `model_selector` 插件自动处理。** 优先级：LongCat → Xiaomi(MiMo) → NV → Google → OpenRouter

创建/修改 cron 任务时，**model 字段必须明确指定**，不得留 null：

| 任务类型 | 基座模型 | 原因 |
|---------|:--------:|------|
| 🌐 复杂任务（多源搜索/HTML生成） | 当前会话模型 | 调度指令需稳定可靠 |
| 💧 简单文本提醒 | 纯脚本（no_agent=true） | 不打 token |
| 📋 看板任务 | model_selector 自动选模 | 自动最优 |

⚠️ **禁止将复杂任务的 model 留 null（继承默认）**，否则切换默认模型时任务会静默漂移。

### 当前任务一览

| 任务 | 时间 | 执行者 | 模型 | 审核 |
|------|:----:|:------:|:----:|:----:|
| 🌅 每日早报 | 每天 8:00 | 莉莉丝 | 当前会话模型 | 🧐 莉莉 |
| 💧 健康喝水 | 每20分 9-19 | 纯脚本 | — | — |
| 💹 金融看板 早 | 每天 10:00 | **⚡ 闪莉** | model_selector 自动选 | 🧐 莉莉 |
| 💹 金融看板 晚 | 每天 20:45 | **⚡ 闪莉** | model_selector 自动选 | 🧐 莉莉 |
| 📰 AI周报 | 周日 20:15 | 莉莉丝 | 当前会话模型 | 🧐 莉莉 |
| 🐙 GitHub周报 | 周日 20:00 | 莉莉丝 | 当前会话模型 | 🧐 莉莉 |

### ⏰ 周日 20:00 峰值隔离（15分钟错峰）

```
GitHub周报  20:00 ─── 启动 ─── 莉莉丝执行
AI周报     20:15 ─── 15min后 ── 莉莉丝执行
金融看板晚  20:30 ─── ⏸️ 已暂停
```

### 闪莉失败降级指引

cron prompt 模板中应明确降级链：
1. 闪莉 delegate_task 失败 → 重试一次（不同 Provider）
2. 仍失败 → **莉莉丝自己执行**（不委派，直接处理）
3. 莉莉丝也失败 → 交付时标注「部分数据缺失」

### 终验检查清单

- ✅ 内容完整、格式正确
- ✅ HTML 文件存在且大小合理（金融看板 >200KB，AI周报 >50KB）
- ✅ 无 "N/A"、"Error fetching" 等异常标记
- ✅ 临时文件/__pycache__ 已清理

## 五、交付校验 🔍

**不成熟的东西，不给冰哥。**

### 校验清单（每次交付前必查）

- ✅ 输出格式是否符合冰哥的预期或要求？
- ✅ 关键数据是否可追溯信源？（不要用二手摘要充数）
- ✅ 子代理生成的代码/命令是否做过安全扫描？（无注入、无危险操作）
- ✅ 多子代理输出之间有无矛盾？矛盾处是否已标注？
- ✅ 临时文件、中间产物是否已清理？
- ✅ 文件杂音是否已清理？（`> file 2>&1` 遗留的控制字符）

### 校验流程

```
我执行完成 → 我逐项检查 → 发现问题？
├── 是 → 自己修正 → 回到检查
├── 否 → 检查任务等级
         ├── ⭐ 简单 → 直接交付
         ├── ⭐⭐⭐ 普通 → 派 🧐 莉莉审核
         │              ├── 通过 → 交付冰哥
         │              └── 不通过 → 返修 → 再审 → 直到通过
         └── ⭐⭐⭐⭐⭐ 重任务 → 派 🚀 大莉M / 大莉D 审核
                           ├── 通过 → 交付冰哥
                           └── 不通过 → 返修 → 再审 → 直到通过
```

### 审核规范

- 🧐 **莉莉**：返回审核报告（问题列表+修改建议）
  - 审核通过 → 交付冰哥
  - 审核不通过 → 返修 → 再送莉莉审 → 直到通过
- 🚀 **大莉M / 大莉D**：同莉莉，但更深度（MiMo / DeepSeek 双通道）
- 默认走 🚀 **大莉M**（mimo-v2.5-pro），大莉D 作为后备
- 多轮不通过（>3轮）→ 停止循环，标记争议项，交付冰哥定夺

## 六、容错与降级 🛡️

| 场景 | 处理方式 |
|------|---------|
| ⏱ 子代理超时（>5min） | 取消该路，用已有结果继续，缺失部分向冰哥说明 |
| ❌ 闪莉竞速全失败 | 降级到 deepseek-v4-flash 兜底 |
| ❌ 某 Provider 全失败 | 自动降级到其他 Provider（NV→OpenRouter→Google→flash 兜底） |
| ❌ flash兜底也失败 | 🚀 **大莉核弹模型最终兜底** |
| ❌ 闪莉mimi竞速全失败 | 降级到 🏠 小莉 本地处理 |
| ❌ **ChatAnywhere 限额耗尽**（返回 429/quota 错误） | 莉莉丝自动检测，降级到 DeepSeek 官方 API |
| ❌ **ChatAnywhere + DeepSeek 官方均失败** | 降级回闪莉竞速链继续兜底 |
| ❌ 莉莉审核超时/不可用 | 降级为莉莉丝自行复核，交付时标注"未经交叉审核" |

## 十、写作辅助技能 📝

4个借鉴 SillyTavern（酒馆）思路的写作辅助技能，提供模板/清单/格式素材。

**定位：** 这4个技能是 `story-long-write`（主流程引擎）的辅助素材库。

| 技能 | 定位 | 提供什么 | 使用时机 |
|------|------|----------|----------|
| **writing-preset** | 看板任务body模板库 | 3种场景模板（长篇日更/短篇/大纲优化） | 创建看板任务时复制粘贴 |
| **writing-guardrails** | 写完章节后的自查清单 | 每章自查 + 每5章检查 + 跨卷检查 | 写完章节后 / 审核时 |
| **character-dialogue-template** | 角色文件中示范对话的格式 | 5种角色类型场景 + 编写技巧 | 创建角色文件时 |
| **context-trigger** | 细纲和任务body中的上下文标注 | 标注格式规范 | 创建细纲时 / 创建任务时 |

### 与 story-long-write 的分工

```
story-long-write = 流程引擎（做什么）
  └─ Phase 1-5、日更、看板调度、审核链

4个辅助技能 = 素材库（用什么）
  ├─ writing-preset → 看板任务body模板
  ├─ writing-guardrails → 写完后的自查清单
  ├─ character-dialogue-template → 示范对话格式
  └─ context-trigger → 上下文标注格式
```

### 使用方式

1. **创建角色文件时** → 按 `character-dialogue-template` 的格式添加"示范对话"
2. **创建细纲时** → 按 `context-trigger` 的格式添加"上下文标注"
3. **创建看板任务时** → 从 `writing-preset` 选模板，嵌入 `writing-guardrails` 的自查清单
4. **写完章节后** → 按 `writing-guardrails` 的清单1逐项自查
5. **每5章后** → 按 `writing-guardrails` 的清单2做阶段性检查

## 十二、历史参考与任务布置规范 📚

### 核心原则
**从成功过的历史中找参考，布置任务时先生成确认没问题再写入。**

### 具体要求

#### 1. 接到新任务时
- **先搜索历史会话**：用 `session_search` 查找类似任务的成功案例
- **分析成功模式**：提取任务要求、执行步骤、审核流程等关键要素
- **参考历史配置**：读取成功任务的具体参数设置

#### 2. 布置任务前
- **先生成任务草稿**：不直接写入，先展示给冰哥确认
- **对比历史任务**：说明与历史任务的异同点
- **确认关键参数**：章节数、字数要求、审核流程等

#### 3. 任务执行中
- **实时监控进度**：发现异常及时报告
- **参考历史经验**：遇到问题时查阅历史解决方案
- **记录新发现**：将本次任务的经验教训保存到知识库

### 监控频率标准
| 任务类型 | 检查间隔 | 说明 |
|----------|----------|------|
| 简单任务（单章修改） | 1-5分钟 | 快速完成的任务 |
| 中等任务（3-5章写作） | 5-15分钟 | 常规写作任务 |
| 复杂任务（7-8章写作） | 15-30分钟 | 大批量写作任务 |
| 审核任务 | 5-10分钟 | 莉莉审核 |

### 示例流程
```
接到"写第四卷第八批"任务
    ↓
搜索历史：session_search("第三卷 写作 批次")
    ↓
分析成功案例：第三卷每批5-7章，任务要求详细
    ↓
生成任务草稿：按第三卷格式，7章/批
    ↓
展示给冰哥确认：任务要求、字数、审核流程
    ↓
确认后写入：创建kanban任务
    ↓
执行中监控：根据任务复杂度选择检查间隔（1-30分钟）
    ↓
完成后记录：保存经验到fact_store
```
