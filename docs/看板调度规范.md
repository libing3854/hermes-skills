# 看板调度规范 📋

> 定义 Kanban 任务的调度逻辑：谁执行、用什么模型、超时重试策略。

---

## 一、Profile 定义

| Profile | 模型 | 对应子代理 | 用途 | 费用 |
|:-------:|:----:|:----------:|:----:|:----:|
| **default** | deepseek-v4-flash | **莉莉** | 审核、复杂任务 | 🟡 免费 |
| **xiaoli** | gemma-4-e4b（本地 4B） | **小莉** | 轻量任务、纯本地操作 | 🟢 免费 |

> 闪莉（mimi/light/deep 模型）和闪莉mimi 由 Ping 系统动态调度，不通过固定 Profile 分配。
> 大莉（deepseek-v4-pro）仅在闪莉全失败时作为核弹兜底，非常规调度。

---

## 二、任务类型 → 执行者映射

| 任务类型 | 执行者 | 模型来源 | 说明 |
|:---------|:------:|:---------|:------|
| 📖 **长篇扫榜/拆文/写作** | ⚡ 闪莉 | Ping light/deep 分类 | 需要较强能力 |
| 📖 **短篇扫榜/拆文/写作** | 🐣 闪莉mimi | Ping mimi 分类 | 轻量任务 |
| 📰 **资讯采集/整理** | ⚡ 闪莉 | Ping light/deep 分类 | 需要联网+分析 |
| 💹 **金融数据处理** | ⚡ 闪莉 | Ping light/deep 分类 | 需要运行脚本 |
| 🧹 **去AI味/审稿** | 🐣 闪莉mimi | Ping mimi 分类 | 纯文本处理 |
| 🔍 **审核任务** | 🧐 莉莉 | deepseek-v4-flash | 交叉审核 |
| 💻 **复杂编程/HTML/渲染** | 🚀 大莉 | deepseek-v4-pro | 核弹任务 |
| 🏠 **本地文件操作** | 🏠 小莉 | gemma-4-e4b | 纯本地

### 分配优先级

1. 按任务类型匹配上表
2. 如果任务声明了 `--assignee`，以声明的为准
3. 如果任务带有 `--skill`，按 skill 的 decompose 逻辑分配
4. 以上都不匹配 → 默认分给 default profile

## 三、超时与重试策略

| 参数 | 默认值 | 说明 |
|:-----|:------:|:------|
| max-runtime | 10m | 普通任务最长执行时间 |
| max-runtime（扫榜） | 15m | 需要搜索多个网站 |
| max-runtime（金融看板） | 5m | 脚本执行较快 |
| max-retries | 2 | 失败后最多重试 2 次 |
| failure_limit | 2 | 连续失败 2 次后变 blocked |

### 超时处理流程

```
任务超时 → SIGTERM → 5s后 SIGKILL → 重试
  ├── 重试成功 → 继续
  └── 重试 failure_limit 次仍失败 → blocked（人工处理）
```

## 四、创建任务时的推荐参数

```bash
# 长篇扫榜（给闪莉）
hermes kanban create "长篇扫榜" \
  --body "..." \
  --max-runtime 15m \
  --skill story-long-scan

# 短篇扫榜（给小莉）
hermes kanban create "短篇扫榜" \
  --body "..." \
  --max-runtime 15m \
  --assignee xiaoli \
  --skill story-short-scan

# 简单文本处理（给小莉）
hermes kanban create "去AI味" \
  --body "..." \
  --max-runtime 5m \
  --assignee xiaoli
```

## 五、看板与工作规范的关系

| | 工作规范（莉莉丝的工作规范.md） | 看板调度规范（本文件） |
|:--|:-------------------------------|:---------------------|
| **范围** | 我主动派活时的决策逻辑 | 看板自动调度时的分配逻辑 |
| **场景** | delegate_task、组合代理模式 | kanban dispatcher 自动分配 |
| **执行者** | 我（莉莉丝）手动选择 | gateway dispatcher 自动调度 |

> **核心原则**：看板调度规范的分配逻辑应与工作规范一致——长篇/复杂任务给闪莉（default），短篇/轻量任务给小莉（xiaoli）。
