# 看板调度规范 📋

> 定义 Kanban 任务的调度逻辑：默认走闪莉，特殊任务才指定。

---

## 一、核心原则

**所有看板任务默认由闪莉执行**，闪莉的模型调用逻辑详见《莉莉丝的工作规范》第三章「闪莉竞速机制」。

```
看板创建任务
  ↓
默认 → ⚡ 闪莉（按工作规范选最快的 mimi/light/deep 模型）
  ↓
特殊任务 → 手动指定（小莉/莉莉/大莉）
```

---

## 二、闪莉模型调用逻辑（引用工作规范）

闪莉的竞速机制和模型选择由工作规范定义，这里只做概要引用：

| 分类 | 模型来源 | 适用场景 |
|:----:|:---------|:---------|
| ⚡ **mimi** | Ping mimi 分类（小模型） | 轻量任务、高峰期替补 |
| 🚀 **light** | Ping light 分类（主力模型） | 日常任务 |
| 🧠 **deep** | Ping deep 分类（强模型） | 深度分析 |
| 🖼️ **vision** | Ping vision 分类（多模态） | 看图/网页/视频 |

详见 `~/.hermes/莉莉丝的工作规范.md` → **三、闪莉竞速机制**

## 三、Profile 定义

| Profile | 模型 | Provider | 对应子代理 | 用途 |
|:-------:|:----:|:--------:|:----------:|:-----|
| **default** | deepseek-v4-flash | DeepSeek 官方 API | 闪莉通道 | 看板任务默认执行，内部调闪莉 |
| **xiaoli** | gemma-4-e4b | 本地 localhost:1234 | **小莉** | 纯本地操作 |

---

## 四、特殊任务指定

非默认情况才需要手动指定：

```bash
# 需要小莉（本地）
hermes kanban create "任务名" --assignee xiaoli

# 需要莉莉（ChatAnywhere 免费通道）
# 目前看板不支持直接指定莉莉通道，需走 default 后手动 delegate_task

# 需要大莉（核弹）
# 闪莉全失败后自动兜底，无需手动指定
```

---

## 五、超时与重试

| 参数 | 默认值 | 说明 |
|:-----|:------:|:------|
| max-runtime | 10m | 普通任务 |
| max-runtime（复杂任务） | 15m | 需要搜索或大量处理 |
| max-retries | 2 | 失败重试次数 |
| failure_limit | 2 | 连续失败后变 blocked |

## 六、与工作规范的关系

| | 工作规范 | 看板调度规范 |
